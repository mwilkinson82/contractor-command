# Document email server-binding follow-up

Status: local proposal only. Do not install or publish this candidate. The installed 0060 migration is unchanged.

The proposal replaces only `public.mcp_document_email_delivery(uuid,text,jsonb)`, after verifying the exact installed 0060 function-body SHA-256. It adds no function, table, policy, grant, role, credential, or OAuth permission. `CREATE OR REPLACE` preserves the existing function owner, security-definer setting, search path, volatility, and ACL; the disposable PGlite test compares these attributes before and after. The original active-membership, actor, company, job, document/version, locking, expiration, confirmation, and one-claim checks remain in the function.

The server now hashes the reviewed actor, company, job, application, version, complete email payload, client PDF digest, account mode, and reported sender. It explicitly accepts `pinned` and `assistant_current_gmail`, rejects missing or unsupported modes, requires a connection ID only for pinned mode, compares a fresh reported observation after locking, cancels on a mismatch, and checks mode/account/hash on receipt. Status and cancellation remain available to legacy rows; legacy rows cannot silently proceed to handoff, claim, or receipt under the replacement. A pre-install read-only inventory and a reconciliation plan for any claimed or uncertain legacy rows are required, because their receipt cannot use the new binding.

**Release blocker: sender identity is not independently verified.** An authenticated authorized caller can fabricate a matching profile address and timestamp in both review and claim. The database can bind and compare these reported values, not prove a Gmail profile lookup occurred or pin a connection. A regression test intentionally demonstrates this. Pinned mode still requires and compares the connection ID, but a caller-supplied ID is not proof that a host actually used that connection. A trusted, authenticated host assertion or an independently verified provider integration is needed before calling the requested sender verification complete. No such credentials, access expansion, or host attestation have been added here. A host-reported provider receipt is not proof of recipient delivery.

`tests/native/document-email-server-binding-races.mjs` and its separate GitHub Actions workflow extend the existing disposable PostgreSQL 17 setup using synthetic identities and actual repository authorization functions. They cover both modes under lock waits, revocation, document-version drift, expiry, claim/cancel and concurrent-claim races, mismatch cancellation, invalid binding, receipt replay, and uncertainty/receipt ordering. They have been syntax-checked but not run: this environment has no complete PostgreSQL service, and the new proposal and tests were intentionally not pushed externally. Hosted CI execution would disclose the proposal and test files to the public repository and must follow normal review/authorization; do not describe PGlite as native concurrency proof.

Focused local results: 72 tests in five suites passed, including 13 proposal tests; TypeScript and production build passed. Independent security review and a real host attachment/identity test remain open. The existing PR 384 and its passing CI were not changed.
