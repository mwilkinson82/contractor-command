# Read-only job accounting evidence

This draft adds chat tool `accounting_report`, signed-in Project Home navigation, `/r/job/<job UUID>/accounting`, source drill-down and a privately downloaded accountant CSV. It changes no financial write handler, access grant, source snapshot, migration or production deployment. AP, AR and PO source owners retain their respective database interfaces.

## Reporting basis

- AR, current internal budget and the PO workflow use USD. AP amounts are grouped by each version's explicitly reviewed currency. There is no currency conversion and no total across different or unknown currencies. A reviewed submission is source provenance, not independent document verification.
- Optional start and inclusive as-of dates. Chat asks only for a missing job; company ambiguity uses existing resolution. Date filters use native same-project GET navigation, so refresh/bookmarks preserve `from` and `as_of` and reset pagination. Invalid/future/reversed dates fail.
- AR selects the highest immutable revision effective through cutoff from evidence known now. This is not a reconstruction of what was known then. Submitted/certified invoice gross and net invoice credits are separate; drafts/voids are excluded. Period billing uses document dates. Unpaid invoices use cumulative active net dues, credits and net allocations through cutoff. Retainage is recorded withheld less released; missing values stay Unknown.
- Cash uses receipt dates and reversal effective dates. Applications and application reversals are not new cash or revenue. Posted credits do not assert refunds. Billed amounts are not earned revenue.
- AP selects the highest immutable **posted** revision whose explicit `accounting_effective_on` is through cutoff. A later unposted revision is excluded. A higher posting with a missing effective date makes the affected as-of amount Unknown; recorded posting/correction timestamps never substitute for business dates. `incurred_on` is retained separately and may be Unknown.
- AP range amounts select the current effective versions whose accounting effective date falls in range. They are **not journal movements or posting deltas**; a corrected version replaces its predecessor, rather than adding another cost. This bounded basis is repeated in UI, chat and CSV.
- Known supported version currencies and amounts roll up separately by currency and cost code. Unknown legacy currency or effective dates remain visible as Unknown rows. A group's complete selected total is Unknown when it contains uncertain rows; a separately labeled known subtotal remains available. Currency codes are pinned to PR351's supported two-decimal list; zero-/three-decimal units are unsupported.
- The USD job-cost metric and current USD budget comparison are populated only when every selected AP allocation has supported dates and reviewed USD currency. Mixed or unknown currency/date coverage withholds the USD aggregate and provisional result. The provisional result, when available, is gross USD billed less net invoice credits less selected USD posted costs, with its incomplete source basis explicit. It is not earned margin, taxable profit or a complete P&L.
- Net AP balances, per-job settlement amounts and shared-header conservation remain Unknown. The snapshot does not supply the necessary job allocation of payments. A currency correction never inherits prior settlement silently. Company-paid expenses are costs, not additional supplier payables or reimbursements. Payment evidence is never another cost or proof of bank transfer/refund.
- Labor, burden, equipment, accruals, cost-category completeness and external accounting coverage are unverified. Cost kinds are not cost categories; supported costs are unclassified by category and retain source cost codes. No entered records does not establish complete history or zero project cost.
- PO commitments are gross internally approved amounts, separate from costs and payments. The highest approved/issued/accepted immutable revision created by cutoff is used with its order date; a later draft does not prove revocation. Internal approval does not prove external acceptance. Fractional-cent line extensions are Unknown rather than rounded using an invented policy. Remaining commitment and bill/PO matching are unsupported.
- Budget is the current known internal budget, not SOV revenue, estimate pricing or CPM task costs. Stored dollars convert exactly to cents; sub-cent/unknown values poison the total. Historical budgets and forecast final cost are not inferred.
- AR, AP, PO and budget are separate reads, not an atomic accounting close. AP's snapshot is atomic only within its own source subsystem. Capture time marks report read start. Preserve the downloaded export for the exact returned evidence; source links remain current signed-in views.

## Source contracts and isolation

Release base: `1fc1bec4f60b2080743cb81e399d7c016f6981dc`, after published PR349.

1. **AR:** `mcp_billing_evidence_get({_job})` checks active membership and full project scope **before any secondary source read**. The consumer validates each returned row's job ID and USD currency. Immutable invoices/versions, receipts, allocations and reversals are retained. Existing billing records provide verified original downloads. No board token grants financial access.
2. **Budget:** signed-in user RLS query of `mcp_job_facts`, selecting exact job and module `budget`, ordered by key, pages of 500 to exhaustion. Errors, duplicate keys and a 10,000-row limit fail rather than yielding partial totals.
3. **AP:** producer PR351 at exact commit `1318fa2a94d7710d8d521093269f099e4e76893a`, `mcp_cost_reconciliation_snapshot({_job})`. Complete v1 envelope binds company/job and owner/AP/full-all-affected-jobs authority. Generic unavailable returns no hidden-record IDs/counts. No fallback to `mcp_cost_submission_read` exists. Supported provenance is `currency_coverage: per_version`, version `currency_code`/`currency_source: reviewed_submission`, `incurred_on`, `accounting_effective_date_coverage: per_posting` and each posting's nullable `accounting_effective_on`. Top-level `currency=null` and `currency_verified=false` correctly indicate that there is no single company currency; they do not suppress supported version-level values. Decimal-string cents are validated before exact BigInt aggregation. Malformed, wrong-scope, unavailable, over-limit or unknown-version source envelopes withhold affected reporting. Legacy v1 without version-level provenance remains evidence-only.
4. **PO:** provisional PR352 `mcp_project_purchase_orders_get({_job})` returns exact job/company orders and immutable versions with declared USD unit-price semantics. Company/job identity is checked. Terms, contacts and default catalogs do not enter this report. No PO migration or write handler is copied/modified.
5. **Shared AR snapshot:** PR355 owns `mcp_billing_reconciliation_snapshot`. No competing snapshot function is introduced. Its reporting projection still needs invoice business/effective dates, gross/net/withheld/released amounts, receipt dates, allocation/reversal effective dates and recorded timestamps before replacing the existing AR reader. Preserve the versioned company/job/completeness envelope. Billing-only atomicity does not make AP/PO/budget reads atomic.

Only signed-in user clients are used. Unexpected permission/transport errors stop reporting rather than pretending a source is absent. Missing optional RPCs and unsupported snapshot contracts return explicit Unknown coverage. Financial data is never read through an admin/service-role route.

## Export and source navigation

UTF-8 CSV has 12 columns: `type,id,date,version,label,cost_code,category,currency,amount_cents,balance_cents,basis_or_source,private_source_url`. It includes capture/basis, limitations, all summaries, budget comparison, AR source ledger, AP currency groups, AP cost-code groups and AP source allocations. Different row types must not be summed together.

Every cell is quoted; quotes/newlines are escaped; leading whitespace/control followed by `=`, `+`, `-` or `@` in text is neutralized. AP exact decimal-string cents carry an apostrophe text prefix to prevent spreadsheet precision loss. Missing amounts/currency remain Unknown. USD display and AP display preserve integer cents without floating-point division.

AR and AP source tables paginate at 50; chat rows are likewise bounded. Totals and CSV always use all returned source rows. Source URLs preserve range, as-of, page and row anchor; after authorized data loads, the selected source disclosure opens and scrolls into view. Original files retain their existing protected route.

## Supported runtime and regression protection

The earlier server failure was a preview target/runtime mismatch. Generic Vite preview expected Node `dist/server/server.js`, while this project emits a Cloudflare Worker under `.output/server`. Transitive Wrangler 4.92.0 used May workerd 1.20260515.1, predating module-scope AbortController support used by MCP SDK 3.0.5. Cloudflare's official change: https://developers.cloudflare.com/changelog/post/2026-08-19-abort-signal-global-scope/.

`npm run preview` now uses pinned official Wrangler 4.154.0 (tested workerd 1.20261023.1), generated worker config, local mode and 127.0.0.1. No SDK patch, compatibility-date/flag, authentication, role/access or transport-route change was made. Use `npm run build`, then `npm run preview -- --port 4622`. The pinned verification tool may be installed via npm's normal cache. Node development's raw WASM import is not the acceptance target for this Workers build.

Both CI workflows also run `npm run verify:preview` after build: real Home/accounting/billing SSR must return HTTP 200, and unauthenticated MCP initialization must remain HTTP 401. The bounded smoke starts on its own local port and cleans up its own process group. Full routed local acceptance now passes; the old server setup blocker is resolved.
