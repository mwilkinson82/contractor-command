# Proposed AP reconciliation read contract

PR351 owns AP records, permissions, writes and migrations. This is an interface proposal for its owner; no AP write handler or schema is changed here. The current `mcp_cost_submission_read(_job)` may omit a split record if the caller lacks full access to every affected job. An empty response therefore cannot establish complete job coverage. The version-1 contract is staged in PR351; this branch consumes its complete result for structural and bounded per-currency checks and fails closed otherwise.

The staged versioned, read-only, single-statement snapshot RPC should be reviewed, bound to the resolved company and job, with an explicit completeness status and no partial financial data when the scope or size bound cannot be satisfied. Its role and membership check must run before access and the all-affected-jobs authorization must be evaluated in the same statement snapshot as the returned records. Do not reveal the identities or count of inaccessible records. When any relevant record cannot safely be returned, give only a generic unavailable status. Apply a documented bounded size, or use a durable snapshot token that binds every page to the same snapshot and actor, scope and expiration; independent paginated reads are not enough.

For complete responses expose only what reconciliation needs: immutable submission IDs and versions with allocation amounts and correction reasons; the effective posted version and approval evidence; settlement IDs, recorded amounts, allocation-to-record, reference and correction lineage. Include source navigation only where the actor is authorized. Amounts must be nonnegative integer cents with a declared exact wire representation and safe range. If shared-payment conservation is claimed, provide an authorized header total and all allocations from the same snapshot; otherwise explicitly mark it unavailable. Keep company-paid expenses out of reimbursement payable calculations. The effective posted version survives a later unposted correction. Payment evidence is not another cost, a confirmed bank transfer or a refund.

Contract tests should include hidden split records, access changes, cross-company/job references, absent RPC, unknown version, oversized data, precision boundaries, immutable corrections, shared-payment consistency and concurrent commits. The checked-in synthetic fixture `tests/fixtures/pr351-cost-read-contract.sql` pins PR351's provisional read-only schema/reader at local commit `f3f02445fa7a52c23cc7dd0f7469ffe9af534ef3`; it does not authorize runtime AP reporting or copy AP write state machines. Revalidate the consumer and entitlement checks against the final reviewed schema and permissions before release.

The test-only snapshot fixture is pinned to PR351 `1318fa2a94d7710d8d521093269f099e4e76893a`; SHA-256 `a25517349efbc2f301341af41e54adcc4ee71fd7df061a20e6c1e9b50dc76f33`. Runtime settlement comparisons require a consistent known posted currency and strictly later recorded single-payment evidence; shared allocations and ambiguous history remain unavailable. Currency is reviewed entry, not independent original-document verification.
