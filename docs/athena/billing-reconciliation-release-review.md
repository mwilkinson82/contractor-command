## Authorization and disclosure

- `SECURITY DEFINER` is necessary for the existing private billing tables. `mcp_assert_active()` checks membership, and `mcp_job_scope(_job) = 'full'` is checked before reading and again in the same statement as the job. The restricted `pg_catalog, public, pg_temp` search path places the system catalog first and temporary objects last; persistent relations and authorization functions are schema-qualified.
- Default `PUBLIC` and `anon` function execution is revoked; `authenticated` receives execute. This is not a general financial grant: the function independently gates membership and exact job access. Direct table permissions remain revoked. Synthetic tests cover anonymous/PUBLIC and authenticated function privileges, direct table denial, assigned PM, unassigned PM, superintendent, contracts, inactive member, unrelated company owner, same job number across companies and temporary-table shadowing. Team membership changes occurring after the statement snapshot are reflected on the next call, as with any database read.
- The RPC returns only the scoped fields needed by the model, but it does return source-reference text to full-scope members. It does not return document filenames, object paths, actors, original bytes or another company's records. The chat layer further returns findings and source navigation rather than the raw ledger. Security/advisor and real role integration review are still required.

## Bounds, indexes and precision

- Each of seven relations is limited to 5,001 rows; any count above 5,000 returns `complete=false` with both evidence payloads null. There is no independent pagination or partial-result fallback. Synthetic tests exercise 5,000 and 5,001 receipts and separately exceed each invoice, invoice-version, allocation, receipt-reversal, document and document-link cap. These caps bound row count, not exact bytes or query duration; source text can be long. Review response-size and execution-time budgets with realistic data before release.
- Existing indexes cover invoice and receipt job IDs, invoice-version job IDs, and document-link job IDs. The staged SQL adds job indexes for allocations, receipt reversals and financial documents. It groups bounded versions once per invoice instead of rescanning the complete version set per invoice. **Standard CREATE INDEX may block writes** and increase storage; inspect existing indexes, data volume and query plans, then choose an approved online/locking strategy and migration transaction boundary. The proposed `CREATE INDEX` statements intentionally do not use `IF NOT EXISTS`, so a naming collision cannot be silently accepted.
- Individual numeric values are checked as safe nonnegative integer cents in the application; sums use `BigInt` and are serialized as decimal strings. Unsupported, unsafe, fractional or missing input makes the affected model unavailable. The hard cap does not prove that historical records were ever entered.

## Synthetic evidence and remaining review

The committed billing schema and proposed SQL run in PGlite. A socket-only isolated PostgreSQL 15.18 test pauses the snapshot statement, commits a receipt with its allocation, and separately commits an invoice correction with allocation and receipt reversals; the reader sees one complete pre-commit state and the next read sees the complete post-commit state. The delay is test instrumentation and is absent from the staged SQL. The test does not establish production index build duration, production query plans, every role's live configuration, or database advisor results.

Before integration: confirm both prerequisite migrations are applied with matching schema; check exact source/migration hash and current permissions; verify managed migration identity and branch collisions; assess the three index builds and plan/timeout limits; run security and performance advisors on an isolated clone; test rollback (drop the snapshot function then the three indexes, preserving all financial evidence); run exact-head CI; and conduct owner acceptance using only seeded synthetic fixtures. Code and migration must be deployed as a coordinated unit. If the RPC is absent, the chat tool reports billing coverage unavailable. AP stays unavailable until its separately reviewed snapshot contract is integrated.

Suggested synthetic acceptance: create a submitted invoice with a partial receipt and posted credit; confirm exact unmatched cents, link an original to the exact invoice version and confirm the missing-link finding clears; create a reversal and verify the prior evidence remains visible; test an oversized job returns unavailable with no partial totals; verify assigned PM versus superintendent, unassigned PM and foreign-company denial. No payments are executed and a recorded payment does not prove a bank transfer.
