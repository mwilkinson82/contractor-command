# Estimating execution and verification

## Candidate scope

- The existing general allowance is 200 calls/hour and 1,000 calls/day, identical across plans, in `src/lib/mcp/limits.ts`, enforced by `guard()` through `mcp_abuse_cap_check`. Its rolling window counts successful `gate` entries, including every prepare and submit. A drawing read is currently charged once per tool invocation, rather than once per estimating session.
- Estimating and drawing tools no longer consume or consult that general allowance. The two verified platform-owner account IDs are also exempt from the general business allowance and the per-heavy-tool volume allowance. Company ownership is not an exemption. Authentication, membership entitlement, job scope, estimating-plan gates, security events and existing extraction protections still run. Other members' PM allowances and per-heavy-tool controls are unchanged. No gateway service is introduced.
- Sheet reads return up to three consecutive target images for all ready lines. `sheet_batch_observations` records them in one host call, and the result includes the next batch. Single-tile submissions remain compatible and also return the next targets. A batch stops before a waiting line joins so line/pass bindings cannot change mid-batch. Existing reads with different saved orders are queued as explicit compatible line groups, rather than restarted or silently narrowed. Visible linear spans may end at a target boundary; whole-area contours still require complete boundary evidence, and unresolved contours never become zero-area quantities. Context is still delivered only on the initial cursor or an explicit reload.
- Each tile retains its original source/version/cursor validation and per-line checkpoint. A failed later tile reports the earlier saved checkpoints and never advances unread coverage. This reduces MCP round trips; database writes remain per line/tile. A fresh 21-tile read can use one initial prepare plus seven batch submissions, excluding setup and review; this is a protocol count, not a live performance or accuracy result.
- The advertised takeoff description is a short factual sentence. The model recommendation appears only in visible card/reply text. No model/classifier steering is advertised.
- The first confirmed scale saves at expected version zero without an extra lookup; an existing region still requires its exact version. A true-size scale confirmation does not need a redundant second flag, and an explicit refusal never saves. Title-block confirmation remains different from independent dimension verification. One to four host-read printed dimensions can verify the saved regional scale in the same call: a known-dimension calibration cannot verify itself with the same endpoints; their labels must match the stated distances, separate endpoints must lie inside the region and touch drawing ink, and the spans must agree with the scale within 1%. Verification appends a calibration revision through the existing save RPC and retains historical calibrations/reads; geometry affected by recalibration remains subject to review. The checks are retained in the calibration reference JSON; Athena performs arithmetic/location checks, not OCR, and text/item identification remains for estimator review. Length, area and volume reads require a source/page-bound calibration; counts require a confirmed region. A unique saved calibration is reused; different named scales are never silently combined.
- The drawing viewer defaults to a measurable line on the displayed sheet. Both the single-line reader and geometry writer refuse a line assigned to another sheet before a checkpoint or geometry write.
- Intake, document review and gap analysis now return complete backend-built native cards, preserving every row and source instead of the generic text card’s eight-line inference; their factual fallback contains no display commands. ChatGPT’s existing legacy card/output template stays unchanged. Intake reconciles every registered drawing source with declared documents, saved spec reviews and contract-clause references, even when the last intake named only A-200. It distinguishes a stored original from a document declaration or extracted text, reports inventory failures rather than asserting absence, and puts scale locking in the next steps.
- Gap findings expose reported high/medium/low confidence and seen/measured/assumed evidence basis. Legacy unrated findings stay explicitly unrated and conservatively displayed; no confidence is invented from a filled quantity. The additive migration preserves RPC guards and grants.
- `estimate_doc_review` saves document-derived scope requirements with a source reference, paragraph/detail citation, excerpt, confidence, evidence basis and current takeoff line mapping; drawing requirements bind to the exact stored source ID/hash and expose superseded or unbound revisions. Unmapped requirements are `Not found` (no mapped takeoff line, not a claim of absence from drawings); instructions remain `Watch`; mapped work remains `Verify` until geometry and required scale checks support `Measured`. All four retain their evidence. A fixed checklist is never presented as full project coverage.
