# Prepared estimating native acceptance

These files prepare tests for an explicitly authorized disposable GitHub Actions
PostgreSQL 17 service. They have not been published or run against native
PostgreSQL. They do not start a server, accept a database URL, apply live SQL,
send email, grant a real account access or change client records.

The portable fixture loads unchanged repository membership, entitlement,
provisioning and current account-privacy scope functions. Seven authorization
bodies are compared to source; the old active-member stand-in table is removed.
Synthetic JWT functions and minimal identity/Storage interface tables are test
adapters. They do not certify the actual Supabase Auth, Hub or Storage HTTP
services. The fixture includes the nine reviewed, unapplied estimating proposals.

Local checks using already installed dependencies:

```sh
node node_modules/vitest/vitest.mjs run src/lib/mcp/estimating-native-fixture.test.ts
node node_modules/typescript/bin/tsc --noEmit -p tests/native/tsconfig.json
node scripts/build-estimating-native.mjs
node --check artifacts/estimating-native/runner.mjs
```

The build helper only bundles the runner. Its raw-text and compiled PDFium
inputs match the existing Node verification adapters; it does not alter app
bundling or stub financial calculations. The actual calculator and mapper
produce frozen-source attestations. Native JSON parameters use postgres.js
`json()` values, while the one legacy PO fixture's serialized line array is
normalized explicitly. JWT and canonical/mapping text remain text.

The local smoke suite exercises actual authorization, a ready frozen $1,815
source, exact export SQL policies, budget acceptance and a package with an
existing selected supplier/approved PO. It remains sequential PGlite evidence.

`.github/workflows/estimating-native-postgres.yml` requires an explicit manual
dispatch or a same-repository PR carrying the approval label
`run-estimating-native`. Publishing or applying that opt-in
requires the applicable authorization; publication alone does not start this
job. The PR route permits verification before merging this new workflow into
the default branch, as GitHub requires default-branch registration for manual
dispatch. It pins Node24.1.0 and records the actual Node/npm versions. Its
`npm ci --legacy-peer-deps` uses the same peer policy as the existing project
verification workflows and must preserve all lock/manifest bytes. The repaired
npm lock preserves the tested package versions and uses verified public sources,
including the required native platform variants. A successful receipt records
the installer versions and hashes. This clean npm verification does not establish
which installer the actual Lovable release uses. Do not replace a failed clean
install with a mutable install or create private-registry credentials implicitly.

The runner accepts only its fixed loopback CI service, synthetic database/user,
run-scoped synthetic password and PostgreSQL 17 container identity, and refuses
an existing Athena schema. It reserves administrator/observer plus two separate
actor sessions and observes real `pg_blocking_pids` barriers before proceeding.
The service and synthetic password exist only in that future disposable job;
no production binding/secret is requested. No local socket/process probe is
needed. The PostgreSQL image uses the official major tag; record the actual
server version/container digest in the authorized run receipt rather than
claiming immutable image bytes from the tag.

Prepared cases cover concurrent pricing, stale source freeze, duplicate freeze,
destination CAS and 101→200 lost-response replay, post-lock membership removal,
reviewed quote replacement without duplicate cost, stale selection and quote
append/omitted-save preservation, duplicate budget/official SOV/draft SOV/buyout
acceptance, budget cancellation/stale/atomic rollback, actual deadlock victim
rollback/fresh retry, historical calculation and preserved awards/POs.

The runner explicitly reports unexecuted coverage: the complete per-writer
geometry/calibration/drawing/clause/GC source matrix; SOV/buyout-specific native
stale/cancel/expiry/rollback permutations; PostgREST warm-member classification;
revocation after the final auth check; hosted signed-link/download/expiry and
original drawing accuracy. A bounded native pass is not full release acceptance.
Use the complete prepared procedure in the external acceptance packet to close
those remaining cases without weakening financial/tenant checks.
